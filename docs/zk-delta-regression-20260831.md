# zk-delta 回归计划（自跑，不需要人参与）

- 写于 2026-08-31，执行者 Claude
- 目的：把「已经落地」升级成「反复可验证」。每一项都必须能**变红**，只会变绿的检查等于没检查。
- 原则：
  1. 每项写清 **输入 / 动作 / 预期 / 判据 / 失败怎么办**，判据必须可证伪。
  2. **合成绿不算绿**——凡是能打真链路的，就打真链路。
  3. 凡是加了新检查的，都要做一次**证伪腿**：人为破坏 → 必须变红 → 还原 → 变绿。
  4. 不删正在服务的 Pod；要制造"服务端状态丢失"用 `rollout restart`（Recreate 策略）。
  5. 不 `kubectl apply` litellm-proxy，不碰网关那一跳。

## 为什么要有这份计划

到目前为止 zk-delta 验过的是**顺风路径**：链路通、模型答对、字节省下来了。
但一个代理真正会害人的时刻不是顺风的时候，是**出岔子的时候**——服务端重启把会话忘了、
小代理被拉起来一次、两条会话同时在跑、上游挂了。这些场景要么只在离线假上游下验过（R1 ③），
要么根本没验过。

**没验过的失败路径 = 上线之后第一次真出事就是线上首演。** 这份计划就是把首演挪到现在。

另外还有一项从头到尾没做过：**真 Cursor GUI 发出来的字节**。之前门① 是我用脚本构造的
`ls` 请求做的对照，不是 Cursor 自己写出来的 body。用户对门① 的原话是「Cursor 发出的简单请求」，
所以这一项必须用真 GUI 补上（R6）。

## R3 · 韧性 / 故障注入（**本轮新增，之前完全没做**）

这一组是这份计划的重点。判据统一是一句话：
**任何失效都必须表现为「硬报错 + 退回全量 + 计数 +1」，绝不能表现为「静默少发历史」。**
因为后者会让上游收到一个残缺的会话，而 HTTP 还是 200——那正是 08-30 翻车的形状。

| # | 场景 | 动作 | 预期 | 判据 |
|---|---|---|---|---|
| R3a | **服务端把会话忘了** | 一条会话跑到第 N 轮 → `rollout restart deploy/zk-delta` → 继续发第 N+1 轮 | 服务端认不出 handle → 409 → 小代理自动重发全量 → 这一轮照样答对 | 409 计数 +1；重建字节仍逐字节相同；模型答案连得上前文（数数不断） |
| R3b | **小代理被重启** | 会话中途 kill 掉小代理进程 | KeepAlive 拉起 → 本地会话表空 → 下一发走全量 | 请求不失败；`full_sent` +1；答案连得上前文 |
| R3c | **两条会话交错** | A1 B1 A2 B2 A3 B3 交替发 | 两条 handle 互不串 | 每条会话各自数数正确；无 409 |
| R3d | **服务端不可达** | 把小代理的增量地址指到一个死端口 | 回落原样透传到今天的地址 | 请求仍 200；`passthru` +1；`fallback_by_reason` 有记录 |
| R3e | **伪造 handle** | 直接对线上服务端发一个不存在的 handle | 409 `delta_base_not_found` | 状态码 == 409，且**没有**被当全量转发 |

失败怎么办：任何一条出现「HTTP 200 但上游收到的历史是残缺的」，**立刻停止推广**，
这是唯一会静默污染上游的失败模式。

### R2 · 集群巡检 —— 报了一发红，查清是误报，规则本身有毛病 [实测]

`audit.sh` 前五组全绿，第 6 组红：`上游非 2xx 1 发`。

按纪律先查数据再下结论。服务端日志里 `up_out=93` 的 turn 有 5 发——`switch.sh` 自检那条
`"hi"` 正好 93 B，说明自检确实会一路穿到上游。证伪腿：再发一发**故意不带 Key** 的自检，
线上计数 `req 76→77`、`upstream_non2xx 1→2`、`upstream_2xx 73 不变`——**+1 请求 +1 非2xx +0 2xx，
一发不多一发不少**。坐实了那一发就是我自己 `switch.sh on` 时不带 Key 的自检，上游回 401。

**不是缺陷，但巡检规则本身是缺陷**：401 是客户端凭据问题，zk-delta 只是忠实透传；
而 400 才是要盯死的那个形状（Cursor 长会话撞入口闸门那条线）。一个见 401 就报漂移的巡检，
喊几次狼之后就没人看了。

修法：服务端加 `upstream_by_status` 分状态码计数；巡检把 401/403 归为「凭据问题、不计入异常」，
400 和其余 4xx/5xx 照报。两个方向都验过 [实测]：

- 打一发 401 → `{"401": 1}` → 巡检 **✓ 计数器全部正常**
- 打一发 400（不存在的模型）→ `{"400": 1, "401": 1}` → 巡检 **✗ 上游硬失败 {"400": 1}（400 尤其要查）**

顺带修掉 `apply.sh` 的一个真 bug：它在 198 上跑 `node --check`，但 **198 根本没装 node**，
所以这一步一直是直接失败退出的。改成本地做语法检查、传过去之后比 **sha256**——
后者才是这一跳真正要证的事（落在 198 上的字节和本地一模一样）。

上线后复验：`apply.sh` 通过，指纹 `d7ffba2adff793e1 → 62c8abc43a665383`，
rollout 成功，**六组全绿**；真链路 5 轮冒烟 VERDICT = PASS（5/5 逐字节相同，数到 "five"）。

### R6 · 真 Cursor GUI —— 这一轮翻出三个真问题

**6.1 `switch.sh on` 直接失败了，而且是两个 bug 叠在一起。** [实测]

报错 `!! 找不到 Cursor 资源目录: /opt/homebrew/Cellar/node/25.9.0_2/Resources/app`。

- bug 1：脚本用**系统 node** 去跑 `cursor_team_setup.js`，而那个安装器是靠 `process.execPath`
  推导 Cursor 安装目录的，必须用 Cursor 自带的 Electron 以 node 模式跑。用系统 node 跑，
  它就去 Homebrew 的 node 前缀底下找 Cursor。
- bug 2：调用没带 `--apply`，就算路径对了也只是 dry-run，什么都不写。

**结论：在此之前 `switch.sh on` 从来没有真的切过 Cursor 的地址。**
文档里那句「只差一条命令 `./zk-delta/switch.sh on`」当时是**假的**。

**6.1b 更要命的是：不能拿那个安装器当开关用。** [实测]

读 `cursor_team_setup.js` 的 `mergeConfig()`（473-477 行）：当选中模型名不以 `cursor-g` 开头时，
它会把 composer / cmd-k 的 `modelName` **覆盖成 `cursor-g-5.6-sol`**。
而查本机 state.vscdb，当前 composer 正是基准 **`cursor-web-fc-82-terra`**。
也就是说，如果我按原计划补上 `--apply` 跑过去，会把门①门② 的基准模型悄悄换掉，
后面所有对照全部作废，而且不会有任何报错。

修法：新写 `zk-delta/cursor_baseurl.js`，只动 `openAIBaseUrl` 一个字段，
写完当场读回来验一条不变量——**把地址换回旧值之后两个 blob 必须完全相同**，
不成立就自动还原并退非零。
证伪腿：故意让它多改一个字段 → sha 从 `2a79a1a3` 变成 `5bf9eb90`（确认真的改到了行）→
退出码 5、自动还原、零残留 → 还原代码 → 恢复正常。[实测]

**6.4 采集把我自己造的样本当成了金样。** [实测]

第一次采完去看 `fixtures/`，3 条都是 93 B 的 `"hi"`——那是 `switch.sh on` 里我自己那条自检
curl，每 `on` 一次落一条。**拿这些让 ⑨ 转绿，就是拿我自己造的样本给自己发绿灯。**
同时 Cursor 启动时那发 `GET /v1/models` 也被采成了 0 字节文件，⑨ 一 `JSON.parse` 就崩。

⚠️ **这个修法只修了一半，见 R9**：门认 UA，而我自己的 live 测试脚本全写死
`UA=Cursor/3.17.19`，门认不出我自己，40 个额度被吃掉 17 个。

修法：采集加两道门——UA 必须是 Cursor（挡掉自检 curl，记 `capture_skipped_ua`），
且必须是有正文的聊天请求（挡掉 0 字节）。污染文件已删。

## 这一轮的教训

1. **「只差一条命令」这种话，在真按下去之前不算数。** `switch.sh on` 写完就没人跑过，
   两个 bug 叠着，路径连 Cursor 都找不到。
2. **装机器和开关不是一回事。** 复用安装器省下的那点代码，代价是它会顺手把基准模型换掉——
   而且是静默的。切地址就该只切地址。
3. **采集口不设门，测试就会拿我自己的输出给自己发绿灯。** ⑨ 差一点就在 3 条自检 `hi` 上转绿。
   证据的来源必须和被验对象无关，这条在采集层就要挡住，不能等到判读时再想起来。
4. **巡检报红，先查是不是巡检自己错了。** 那一发「上游非 2xx」是我自己的自检 401——
   顺着查下去发现真正的毛病是「把 401 和 400 炖成一个数」。见红就调宽阈值是自欺，

### 这一轮的教训

1. **取证的门要认被验对象伪造不了的东西。** 我把门设在采集层是对的（12.3 ③），
   但认 UA 等于没设——UA 在我自己手里。
2. **出处必须在采集当场记。** 事后靠 body 大小猜是真抓包还是自己造的，那是猜不是证据。
3. **字段只写自己真能证到的那一步。** 写 `gui` 就是没证据的断言，写 `gate_passed` 才是事实。
4. **配额要按持久状态算，不是按本进程算。** 封顶存在的理由（别写爆磁盘）恰恰是跨重启才成立的。
5. **`.gitignore` 别靠通配符枚举扩展名。** `fixtures/*.json` 挡不住 `_manifest.jsonl`，差一个字母。
6. **修完一处要回头看同类判据有没有同样的病。** 12.3 ③ 修的是「别采自检 curl」，
   却没问「我的测试脚本算不算自己」——**同一个问题的第二个实例，我漏了。**

# 升级驾驶台（gray console）设计

## 一句话

在现有灰度状态机外面套一层「L3 驾驶」：**顺的时候机器自己往前开，碰到它判断不了的事就停在安全位置、
把选项摆出来等人拍板**。驾驶台**只调用现有脚本**，不改任何现有脚本的行为；关掉驾驶台，现有命令行流程照常可用。

## 不许破坏的东西（硬约束）

1. 现有脚本（`scripts/gray-*.sh`、`scripts/run/*.sh`、`check-*.py`）一行不改语义。驾驶台通过子进程调用它们，
   和人在终端敲命令走同一条路、同一把锁（`_lib.sh lock_acquire`）、同一套 gate evidence。
2. 驾驶台挂了 / 被停了 = 什么都不发生。它不持有路由状态；真相仍在 `/etc/nginx/gray-route/active`。
   重启后从磁盘重新读状态，不靠内存。
3. 自动止损（monitor loop → dispatcher → `gray-global-rollback.sh`）**不经过驾驶台**，仍然独立运行。驾驶台只是
   能看见它、并在它触发后把「为什么回退」讲清楚。
4. 同一时刻只允许一个「驾驶者」：驾驶台执行动作前抢 `$D/.console.lock`（flock）；人在终端手工跑 run/ 脚本时
   驾驶台看见 `.console.lock` 被别人持有就进入「人工接管」只读模式。
5. 默认只监听 `127.0.0.1`；10-18 起可 `--bind 10.68.13.198 --allow <内网段>` 内网直连（源 IP 白名单 + 写操作口令）。不开公网端口、不改 nginx。

## 借鉴（调研结论）

| 来源 | 借什么 |
|---|---|
| Argo Rollouts | 分析结果三态：**成功 / 失败 / 不确定（Inconclusive）**；不确定 ⇒ 暂停等人，而不是当失败也不是当成功 |
| Flagger | 推进条件「连续 N 个检查周期都过」，而不是看一次 |
| Spinnaker Manual Judgment | 决策点有明确的选项、说明和**超时后的默认动作**；默认动作必须是安全的那个（停/不前进） |
| Kayenta | 「勉强过（marginal）」单列一档 ⇒ 交给人 |
| SAE J3016 L3 | 「接管请求」：系统在自己能力边界外**提前**请求接管，并在人没接时进入「最小风险状态」 |
| Bainbridge《自动化的讽刺》 | 人长期不碰会失去手感 ⇒ 每个决策点都要把「现在发生了什么、证据、每个选项的后果」写清楚，不能只给一个红灯 |

## 我们自己的「设计运行域」（ODD）——机器可以自己开的条件

全部满足才自动推进；任一不满足 ⇒ 不前进，进入决策点：

- 当前档已驻留够时间（1/5/10 档 25 分钟、50/100 档 30 分钟），且本 generation ≥5 个 monitor 周期全 `rc=0`
- 新版 5xx 率 ≤ 旧版 + 1 个百分点（新版样本 <50 时不判，算「样本不足」）
- 新版每 pod `worker_killed=0`、重启数不变
- 自动止损没有触发（phase 不是 `rolled_back`）
- ≥50% 档：容量检查 PASS 且证据属于本 run 本 generation；guarded-old 全 Ready、健康 200

## 三态判定 → 动作

| 判定 | 例子 | 动作 |
|---|---|---|
| **通过** | 上面全满足 | 自动推进下一档，事件流记一条 |
| **不确定** | 新版样本太少；容量 `UNPRICED_CLASS`；monitor 周期不够但没坏 | 继续驻留，超过 2 倍驻留时间仍不确定 ⇒ 升级为决策点 |
| **失败** | worker 被杀；新版 5xx 明显高；容量不足；guarded-old 不健康 | 停在当前档（不前进、不后退），立刻出决策点 |
| **已被自动回退** | phase=`rolled_back` | 停，出「看原因 → 关 run 重开 / 结束」决策点，附回退那一刻的 metrics 证据和归因 |

决策点**永远不会因为没人回答而前进**。没人回答 = 保持现状（当前档继续跑，止损照常武装）。

## 必须人拍板的步骤（无论多顺）

1. 开始灰度（进 normal_gray + 试点）
2. 收敛：把生产本体换成新版（§7 converge）
3. 收敛提交（commit：流量回到新 prod）
4. 任何回退 / 关 run

其余放量档位按 ODD 自动走。用户可以在页面上把「自动推进」关掉，变成每档都问。

## 页面（单页，中文，说人话）

- 顶部一句话状态：「现在 10%，第 3/5 档，已稳定 18 分钟，再 7 分钟自动升到 50%」
- 进度条：试点 → 1 → 5 → 10 → 50 → 100 → 生产换新 → 完成，当前档高亮
- 三块读数（新版 vs 旧版并排）：错误率、请求量、worker 被杀/重启、monitor 周期
- 决策卡（有才出现）：发生了什么（一句话）/ 证据 / 我的建议 / 选项按钮（每个写清后果）/ 不选会怎样
- 事件流：每一步做了什么、谁做的（机器/人）、依据
- 「暂停自动」开关、「停下来别动」按钮（只停驾驶台，不碰路由）

## 实现

- `console/server.py`：Python 标准库 `http.server`（198 没有 fastapi；不装新依赖），只监听 127.0.0.1:8795
- `console/engine.py`：只读采集（state.env、monitor 日志、nginx 日志、kubectl、SpendLogs 只读查询）+ 判定（纯函数，可测）
- `console/actions.py`：动作白名单，每个动作 = 调一个现有脚本；页面只能触发白名单里的动作
- `console/static/index.html`：单文件前端，轮询 `/api/state`
- 后台线程每 60 秒评估一次；自动推进只调用 `scripts/run/step.sh <next> 0`（驻留已由引擎判过）
- 所有决策和动作写 `$D/console-events.jsonl`（append-only）
- 测试：判定逻辑全部纯函数单测，用 10-17 那晚的真实读数做回放用例（spend 探针 402、杭州 key、capacity 残留证据）
